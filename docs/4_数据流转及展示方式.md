## 二、主要数据流转链路

### 2.1 久坐提醒数据流

#### 流程图

```
┌─────────────┐
│  设备传感器  │
│ (加速度计)   │
└──────┬──────┘
       │
       │ 原始传感器数据（50Hz采样）
       ▼
┌─────────────────────────┐
│ 前端: SedentaryReminder  │
│  Service                │
│ 1. 数据降噪              │
│ 2. 姿态识别              │
│ 3. 久坐计时              │
└──────┬──────────────────┘
       │
       │ 久坐时间达到阈值（如60分钟）
       ▼
┌─────────────────────────┐
│  前端: 本地提醒           │
│  (通知/震动)              │
└──────┬──────────────────┘
       │
       │ POST /api/reminder/log
       ▼
┌─────────────────────────┐
│ 后端: ReminderController │
└──────┬──────────────────┘
       │
       │ 插入 remind_log
       ▼
┌─────────────────────────┐
│    MySQL: remind_log    │
└─────────────────────────┘
```

#### 数据细节

| 阶段      | 数据类型         | 数据大小     | 传输频率       |
| ------- | ------------ | -------- | ---------- |
| 传感器原始数据 | 加速度计/陀螺仪三轴数据 | 约24字节/采样 | 50次/秒      |
| 前端处理后数据 | 姿态状态、久坐时长    | 约50字节/状态 | 1次/分钟      |
| 提醒日志    | 提醒时间、状态      | 约200字节/条 | 按需（如每小时1次） |

### 2.2 微运动推荐数据流

#### 流程图

```
┌────────────────────────────────────────────────────────────────────┐
│                        用户请求推荐                                  │
│  输入: target_body_part, preference_override                        │
└────────────────────────────┬───────────────────────────────────────┘
                             │
                             ▼
┌────────────────────────────────────────────────────────────────────┐
│  后端: MicroMotionController.generatePrompt()                       │
└────────────────────────────┬───────────────────────────────────────┘
                             │
        ┌────────────────────┼────────────────────┐
        │                    │                    │
        ▼                    ▼                    ▼
┌───────────────┐    ┌───────────────┐   ┌───────────────┐
│ 加载用户信息   │    │ 加载偏好画像   │   │ 加载历史反馈   │
│ (user表)      │    │(user_preference│   │(exercise_record│
└───────┬───────┘    └───────┬───────┘   └───────┬───────┘
        │                    │                    │
        └────────────────────┼────────────────────┘
                             │
                             ▼
┌────────────────────────────────────────────────────────────────────┐
│  阶段一: VideoService.recommendActionCandidates()                   │
│  1. 从动作库读取所有视频元数据                                          │
│  2. 计算每个动作的召回分 recall_score                                  │
│  3. 排序 + 多样性筛选                                                 │
│  输出: 候选动作池（10-20个）                                           │
└────────────────────────────┬───────────────────────────────────────┘
                             │
                             ▼
┌────────────────────────────────────────────────────────────────────┐
│  阶段二: DeepSeekService.callDeepSeek()                             │
│  1. 构建提示词（包含候选池、用户上下文）                                 │
│  2. 调用 DeepSeek API                                               │
│  3. 解析返回结果，提取:                                               │
│     - 最终动作列表                                                   │
│     - 每个动作的 llm_rerank_score                                   │
│     - 选择理由 llm_reason                                           │
└────────────────────────────┬───────────────────────────────────────┘
                             │
                             ▼
┌────────────────────────────────────────────────────────────────────┐
│  结果组装与持久化                                                    │
│  1. 计算 normalized_recall_score                                   │
│  2. 计算 final_score                                                │
│  3. 插入 exercise_record                                            │
│  4. 批量插入 recommendation_trace                                   │
└────────────────────────────┬───────────────────────────────────────┘
                             │
                             ▼
┌────────────────────────────────────────────────────────────────────┐
│  返回推荐结果给前端                                                  │
│  包含: actions, exercise_record_id, recommendation_summary          │
└────────────────────────────────────────────────────────────────────┘
```

#### 数据细节

| 阶段         | 数据类型                  | 数据大小      | 说明             |
| ---------- | --------------------- | --------- | -------------- |
| 请求         | 推荐请求JSON              | 约100字节    | 目标部位、偏好覆盖      |
| 阶段一输入      | 用户画像数据                | 约2KB      | 用户信息、偏好、历史反馈   |
| 阶段一输出      | 候选动作池                 | 约5-10KB   | 10-20个候选动作及召回分 |
| DeepSeek请求 | 提示词Prompt             | 约3-5KB    | 含候选池、用户上下文     |
| DeepSeek响应 | LLM返回JSON             | 约1-2KB    | 重排结果、选择理由      |
| 数据库写入      | exercise\_record      | 约2KB/条    | 运动记录主表         |
| 数据库写入      | recommendation\_trace | 约5-10KB/批 | 10-20条推荐追踪记录   |
| 响应         | 推荐结果JSON              | 约2-3KB    | 最终推荐方案         |

### 3.2 核心页面数据展示

#### 3.2.1 3D身体部位选择页面

**展示元素：**

- 3D人体模型（居中展示，支持旋转缩放）
- 身体部位高亮（点击时高亮对应部位）
- 部位名称标签
- 确认选择按钮

**数据来源：**

- 前端静态资源：`assets/models/human_body.glb`
- 前端常量：`body_part_catalog.dart`

**交互反馈：**

- 模型旋转：拖拽手势
- 缩放：双指捏合
- 部位选择：点击对应部位 → 高亮 → 显示名称

#### 3.2.2 推荐结果页面

**展示元素：**

- 推荐摘要卡片（顶部）
  - 推荐理由文字
  - 命中偏好标签（圆角矩形标签）
- 动作列表（垂直滚动）
  - 每个动作卡片
    - 视频缩略图
    - 动作名称
    - 时长
    - 难度标签
    - 目标部位标签
    - 选择理由（小字说明）
- 开始跟练按钮

**数据来源：**

- API响应：`POST /api/micro-motion/generate-prompt`

#### 3.2.3 视频播放页面

**展示元素：**

- 视频播放器（全屏/嵌入）
  - 播放/暂停按钮
  - 进度条
  - 时长显示
  - 全屏切换
- 动作说明文字（视频下方）
- 倒计时/进度提示
- 完成按钮
- 反馈表单（完成后显示）
  - 反馈标签：太简单/刚好/太难/不喜欢
  - 评分星级（1-4星）

**数据来源：**

- 视频流：Nginx静态文件服务
- 视频元数据：`GET /api/video/{id}`

#### 3.2.4 健康数据页面

**展示元素：**

- 统计概览卡片
  - 本周运动次数
  - 累计运动时长
  - 连续打卡天数
- 趋势图表（fl\_chart）
  - 周运动时长折线图
  - 部位分布饼图
  - 反馈统计柱状图
- 历史记录列表
  - 每次运动的时间、动作、时长、反馈

**数据来源：**

- API响应：`GET /api/health/data`

### 4.2 数据缓存策略

| 数据类型   | 缓存位置                   | 缓存时长 | 刷新策略    |
| ------ | ---------------------- | ---- | ------- |
| 用户信息   | 前端 shared\_preferences | 7天   | 登录时刷新   |
| 视频元数据  | 后端内存 / Redis (预留)      | 1小时  | TTL过期刷新 |
| 用户偏好画像 | 后端内存                   | 5分钟  | 反馈后刷新   |

### 4.3 数据归档策略

| 数据表                   | 归档条件  | 归档周期  |
| --------------------- | ----- | ----- |
| exercise\_record      | 超过1年  | 每年一次  |
| recommendation\_trace | 超过1年  | 每年一次  |
| remind\_log           | 超过6个月 | 每季度一次 |
| device\_data          | 超过3个月 | 每月一次  |

## 五、网络传输优化

### 5.1 视频流优化

- **协议：** HTTP/2 或 HTTP/3
- **编码：** H.264 / H.265
- **码率自适应：** 根据网络带宽自动调整
- **分片传输：** 支持边下边播
- **CDN加速：** 生产环境推荐使用CDN分发

### 5.2 API数据优化

- **压缩：** Gzip / Brotli 压缩
- **分页：** 列表接口支持分页
- **按需加载：** 只请求必要字段
- **批量请求：** 支持批量获取视频信息

### 5.3 数据流量估算

#### 单日活跃用户（DAU）= 1000

| 数据类型        | 单次流量   | 人均每日次数 | 日总流量    |
| ----------- | ------ | ------ | ------- |
| API请求（不含视频） | \~5KB  | 20次    | \~100MB |
| 视频播放        | \~30MB | 3次     | \~90GB  |
| 合计          | -      | -      | \~90GB  |

#### 月度流量（按30天）

| 类型    | 月度流量    |
| ----- | ------- |
| API流量 | \~3GB   |
| 视频流量  | \~2.7TB |
| 合计    | \~2.7TB |
